pymmcore_gui ¶

A Micro-Manager GUI based on pymmcore-widgets and pymmcore-plus.

Submodules

Name Description
actions Actions: the commands behind pymmcore-gui's menus, toolbars and dock widgets.
widgets Widgets that pymmcore-gui adds to those in pymmcore-widgets.

Classes

Name Description
ActionInfo Information for creating a QCoreAction.
CoreAction Actions that act on the global CMMCore instance.
MicroManagerGUI Micro-Manager minimal GUI.
WidgetAction Widget Actions toggle/create singleton widgets.

Functions

create_mmgui Initialize the pymmcore-gui application and Main Window.

get_widget(key: str, create: bool = ...) -> QWidget

get_widget(key: str, create: bool = True) -> QWidget

Get (or create) widget for key ensuring that it is linked to its QAction.

If the widget has been "closed" (hidden), it will be re-shown.

Note that all widgets created this way are singletons, so calling this method multiple times will return the same widget instance.

Parameters:

Name Type Description Default
key WidgetAction

The widget to get.

 required
create bool

Whether to create the widget if it doesn't exist yet, by default True.

 True

Raises:

Type Description
KeyError

If the widget doesn't exist and create is False.

get_dock_widget ¶

get_dock_widget(key: str) -> CDockWidget

Get the QDockWidget for key.

Note, you can also get the QDockWidget by calling get_widget(key), and then calling widget.parent(). The parent will either be an instance of QDockWidget (if it's actually a docked widget), or MicroManagerGUI, if it's not docked. You should use isisinstance in this case to check.

Parameters:

Name Type Description Default
key WidgetAction

 required

restore_state ¶

restore_state(*, show: bool = False) -> None

Restore the state of the window from settings (or load default state).

show is added as a convenience here because it may be a common use case to restore the state in a single shot timer and (only) then show the window. This avoids the window flashing on the screen before it is properly positioned.

Functions¶

create_mmgui ¶

create_mmgui(
    *,
    mm_config: Path | str | None | Literal[False] = None,
    mmcore: CMMCorePlus | None = None,
    install_sys_excepthook: bool = True,
    install_sentry: bool = True,
    exec_app: bool = True,
) -> MicroManagerGUI

Initialize the pymmcore-gui application and Main Window.

This is the primary way to start pymmcore-gui. (It is also called by __main__.main() when running from the command line.)

Parameters:

Name Type Description Default
mm_config str | None | False

The path to the Micro-Manager configuration file to load. - If False, no configuration will be loaded. - If a non-empty string, that configuration will be loaded. - If None (or the empty string), auto-deciding logic will be used based on the stored user settings (based on the settings values for Settings.last_config and Settings.auto_load_last_config).

 None
mmcore CMMCorePlus | None

The CMMCorePlus instance to use. If None (default), the global CMMCorePlus.instance() will be used if it exists, or a new (global) instance will be created (which you may access later with CMMCorePlus.instance()). Note: you may wish to also pass mm_config = False to prevent loading a system configuration, if you have already loaded one in your instance.

 None
install_sys_excepthook bool

If True (the default), installs a custom excepthook that does not raise sys.exit(). This is necessary to prevent the application from closing when an unhandled exception is raised in the main thread.

 True
install_sentry bool

If True (the default), the user will be given an option to send error reports to the developers, unless they have previously opted in/out. If False, no prompt will be shown, and no error reports will be sent.

 True
exec_app bool

If True (the default), the QApplication event loop will be started. If False, the event loop will not be started, and the caller is responsible for starting it with QApplication.instance().exec().

 True
